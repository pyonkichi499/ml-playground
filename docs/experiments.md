## はじめに

- サイドバー上部の **データ** の設定 (データセット・サンプル数・ノイズ・シード・テストの割合) は、プレイグラウンドとハイパーパラメータ探索の両ページで共通です。ページを移動しても値は保持されます。
- 設定欄に書いていない項目は、アプリの既定値のままにしてください。データの既定値は Moons / サンプル数 200 / ノイズ 0.20 / シード 42 / テストの割合 0.30 です。多くの実験ではノイズを **0.30** に上げます (効果が見やすくなるため)。
- 本文の数値は、書かれた設定 (シード 42) で実際に確認した値です。シードを変えると数値は変わりますが、傾向はたいてい同じです。
- テストデータはこの設定では 60 点しかありません。正解率 0.9 付近でも、偶然だけで ±0.04 程度 (標準誤差 √(0.9×0.1/60) ≈ 0.039) はぶれます。小さな差で結論を出さないでください。

### 1. ロジスティック回帰: C と L1 正則化

**ねらい** — 正則化を強くすると係数が小さくなることを確かめる。L1 では係数がちょうど 0 になり、使う特徴量そのものが減ることを見る。

**設定**
- データ: Moons、サンプル数 200、ノイズ **0.30**、シード 42、テストの割合 0.30
- モデル: ロジスティック回帰。多項式特徴量の次数 (degree) = **10**
- 正則化の種類 (penalty) = **L1**、正則化の逆数 (C) を **100 → 10 → 1 → 0.1 → 0.01** と動かす
- 最後に penalty を **L2** に切り替えて、同じように C を動かす

**観察すること**

degree 10 では特徴量が 65 個 (x1, x2, x1², x1·x2, …, x2¹⁰) できます。

| C | L1: 非ゼロ係数の数 | L1: 訓練 / テスト | L2: 非ゼロ係数の数 | L2: 係数ノルム ‖w‖ |
|---|---|---|---|---|
| 100 | 25 | 0.943 / 0.867 | 65 | 26 |
| 10 | 13 | 0.921 / 0.867 | 65 | 9.52 |
| 1 | 7 | 0.871 / 0.867 | 65 | 3.2 |
| 0.1 | 3 | 0.814 / 0.867 | 65 | 1.16 |
| 0.01 | 0 | 0.500 / 0.500 | 65 | 0.408 |

- L1 では C を小さくするたびに「係数」の図で灰色の点 (ちょうど 0 の係数) が増えます。C = 0.1 で残るのは x1, x2, x1³ の 3 つだけです。
- C = 0.01 では係数が全部 0 になります。全ての点を同じクラスと予測するので、正解率は 0.500 です。
- L2 では非ゼロ係数は常に 65 個のままです。係数ノルムは小さくなりますが、ちょうど 0 になる係数はありません。
- C = 100 から始めるのは、C = 1000 の L1 では「収束」が「いいえ」(反復の上限で打ち切り) になるからです。打ち切られた解では、係数がまだ動いている途中かもしれません。

**なぜそうなるか** — C は正則化の強さの逆数です。C が小さいほど「係数を小さく保つ」罰の比重が大きくなります。L2 の罰 (係数の二乗和) は 0 の近くで傾きが 0 になるので、係数は 0 に近づいても 0 ちょうどにはなりません。L1 の罰 (係数の絶対値の和) は 0 でも一定の強さで押し続けるので、効果の小さい係数はちょうど 0 で止まります。そのため L1 は特徴選択の役目も果たします。

### 2. k近傍法: k = 1 → 25 → 50

**ねらい** — モデルの複雑さを 1 つのつまみで動かし、過学習 (訓練データに合わせすぎ) と未学習を目で見る。

**設定**
- データ: Moons、サンプル数 200、ノイズ **0.30**、シード 42、テストの割合 0.30
- モデル: k近傍法 (k-NN)。投票の重み = 均等 (uniform)、距離の測り方 = ユークリッド (p=2)
- 近傍の数 (n_neighbors = k) を **1 → 25 → 50** と動かす

**観察すること**

| k | 訓練の正解率 | テストの正解率 |
|---|---|---|
| 1 | 1.000 | 0.800 |
| 25 | 0.914 | 0.900 |
| 50 | 0.850 | 0.933 |

- k = 1 では決定境界がギザギザで、相手クラスの領域に食い込んだ 1 点の周りにも小さな「島」ができます。訓練の正解率は 1.000 なのに、テストとの差は 0.2 もあります。
- k = 25 では境界がなめらかになり、訓練とテストの差がほぼ消えます。
- k = 50 では境界がさらに単純になり、訓練の正解率もさらに下がり (0.850)、「k と正解率」の図の CV の線も下がります。これが未学習の兆候です。
- 「k と正解率」の図には、train (訓練)、5-fold CV (訓練データだけで交差検証)、test (reference only) の 3 本の線があります。train の線は k とともに下がっていきます (k = 1 で 1.0、k = 51 で 0.857)。CV の線は k = 1 で 0.857 と低く、k = 7 で最大 (0.914) になり、k = 51 では 0.814 まで下がります。過学習と未学習の両方が、CV の線にはっきり出ます。
- ★ (best CV: k=7) は CV で選んだ k です。test の線は 0.90〜0.93 の間を上下していて、k の選択には使いません (reference only)。テストの結果を見て k を選ぶと、テストがもう「未知のデータ」ではなくなるからです ([実験 10](#exp-test-once) を参照)。

**なぜそうなるか** — k = 1 の予測は「いちばん近い訓練点のクラス」なので、訓練点を自分自身で必ず当てます (訓練の正解率 1.000)。ノイズで反対側に入り込んだ点もそのまま覚えてしまいます。k を大きくすると多数決の平均効果でノイズが消えます。ただし k が大きすぎると、近傍が月の形を越えて広がり、本当の曲がり方も均されてしまいます。
この設定ではテストが 60 点しかないため、k = 50 でもテストの正解率は下がりませんでした (0.933)。テストの 1 点は正解率 0.017 に当たるので、60 点では偶然のぶれが大きいのです。未学習は、訓練の正解率、境界の形、CV の線で判断してください。**発展**: テストの割合を 0 にすると、200 点全部が訓練データになり、CV の線がより安定します。このとき最良の k は 11 (CV 0.925) で、k = 51 では 0.865 でした。

### 3. ガウス生成モデル: Circles で LDA と QDA

**ねらい** — 「クラスごとのデータはこういう形の楕円に広がっている」というモデルの仮定が、データに合わないと何が起きるかを見る。

**設定**
- データ: **Circles**、サンプル数 200、ノイズ 0.20、シード 42、テストの割合 0.30
- モデル: ガウス生成モデル (Naive Bayes / LDA / QDA)。事前確率はデータの比率から推定 (既定のまま)
- モデル (variant) を **LDA → QDA → Naive Bayes** と切り替える

**観察すること**

| variant | 訓練 | テスト | 境界の形 |
|---|---|---|---|
| LDA | 0.521 | 0.483 | 直線 |
| QDA | 0.864 | 0.917 | 内側の円を囲む閉じた曲線 |
| Naive Bayes | 0.871 | 0.900 | 内側の円を囲む閉じた曲線 |

- LDA の正解率はほぼ 0.5 で、当てずっぽうと変わりません。「クラスごとの分布 p(x | y)」の図では、2 クラスの楕円がほとんど重なっています。
- QDA では内側のクラスに小さな楕円、外側のクラスに大きな楕円が推定され、その間に円に近い境界ができます。
- Naive Bayes でも QDA とほぼ同じ結果になります。

**なぜそうなるか** — Circles の 2 クラスは、どちらも中心が原点付近にあります。違うのは広がり (分散) だけです。LDA は「全クラスが同じ形の楕円 (共通の共分散行列)」を仮定するので、クラスを区別する手がかりは中心の位置しかありません。中心がほぼ同じなので、境界の直線は意味のない向きに引かれます。QDA はクラスごとに楕円の大きさを変えられるので、「小さな楕円」と「大きな楕円」の境目として円形の境界が作れます。Naive Bayes はクラスごとに軸に平行な楕円を仮定します。ここではどちらのクラスも円形に広がっているので、その仮定で十分です。

### 4. 決定木: 深さとテストの正解率

**ねらい** — 木を深くすると訓練の正解率は上がり続けるのに、テストの正解率は上がらないことを確かめる。

**設定**
- データ: Moons、サンプル数 200、ノイズ **0.30**、シード 42、テストの割合 0.30
- モデル: 決定木。分割基準 = gini、葉ノードの最小サンプル数 = 1
- 木の深さ (max_depth) を **1 → 2 → 3 → 5 → 8** と動かし、最後に「max_depth を制限しない (None)」にチェックする

**観察すること**

| max_depth | 実際の深さ | 葉の数 | 訓練 | テスト |
|---|---|---|---|---|
| 1 | 1 | 2 | 0.814 | 0.833 |
| 2 | 2 | 4 | 0.871 | 0.867 |
| 3 | 3 | 6 | 0.871 | 0.867 |
| 5 | 5 | 15 | 0.957 | 0.833 |
| 8 | 8 | 21 | 0.993 | 0.817 |
| None | 9 | 22 | 1.000 | 0.800 |

- 深さ 1 は直線 1 本 (軸に平行) の境界です。深さ 2〜3 で月の形を大まかにとらえます。
- 深さ 5 以上になると、境界に細かい長方形の出っ張りが増えます。葉の数は 22 まで増え、訓練の正解率は 1.000 に達しますが、テストの正解率は 0.867 から 0.800 に下がります。
- 制限しない (None) にしても、実際の深さは 9 で止まります。この時点で全ての葉が 1 クラスだけになり、それ以上分ける理由がないからです。

**なぜそうなるか** — 決定木は訓練データの不純度 (gini) が下がる限り分割を続けます。浅いうちは本当の形を学びますが、深くなると 1〜2 点しか含まない葉を作って、ノイズの点を個別に囲い込み始めます。こうした分割は新しいデータには当てはまりません。そのため、訓練とテストの差 (過学習の大きさ) は深さとともに広がります。**発展**: 深さを制限しない (None) のまま、葉ノードの最小サンプル数を 10 にしてみてください。実際の深さは 5、葉の数は 10 になり、訓練 0.857 / テスト 0.850 と差がほぼ消えます。深さの制限とは別の方法で、細かすぎる葉を防げます。

### 5. ランダムフォレスト: 木 1 本と 100 本

**ねらい** — 深い木 1 本はばらつきが大きいが、たくさん平均するとばらつきが減ることを見る。木を増やすと、テストの正解率は途中で頭打ちになる。

**設定**
- データ: Moons、サンプル数 200、ノイズ **0.30**、シード 42、テストの割合 0.30
- モデル: ランダムフォレスト。max_depth を制限しない (None)、候補にする特徴量の数 (max_features) = 1、ブートストラップ = オン、葉ノードの最小サンプル数 = 1 (いずれも既定)
- 木の数 (n_estimators) を **1 → 10 → 100** と動かす

**観察すること**

| 木の数 | 訓練 | テスト | OOB 正解率 |
|---|---|---|---|
| 1 | 0.950 | 0.817 | — |
| 10 | 0.993 | 0.850 | — |
| 100 | 1.000 | 0.917 | 0.893 |

- 「個々の木 vs フォレスト」の図では、1 本 1 本の木の境界が長方形だらけで、木ごとにまったく違う形をしています。右下のフォレスト (100 本の平均) の境界は、それらよりずっと月の形に近くなります。
- 「木の数と正解率」の図では、テスト曲線が最初の 10 本あたりまで大きく上下しながら上がり、その後は 0.90〜0.93 付近で横ばいになります。破線 (木 1 本のテスト正解率の平均) は約 0.84 です。
- 100 本でも **訓練の正解率は 1.000** です。深い木を平均しても、訓練データはすべて覚えています。訓練の正解率では汎化性能はわかりません。汎化性能の見積もりには OOB 正解率 (0.893) を使います。OOB 正解率は、各点を「その点を学習に使わなかった木」だけで予測したときの正解率で、訓練データだけから計算できます。

**なぜそうなるか** — 深さ制限のない木は、訓練データの小さな違いで形が大きく変わります (分散が大きい)。フォレストでは、各木を別々のブートストラップ標本で学習し、分割ごとに候補の特徴量もランダムに選ぶので、木どうしの誤りが似なくなります。似ていない誤りは平均すると打ち消し合うので、分散が減ります。一方、木どうしの相関は残るので、ある本数から先は増やしても改善しません。木を増やしても過学習が悪化することはありませんが、それぞれの木が持つ過学習 (訓練 1.000) が消えるわけでもありません。n_estimators は「多ければ多いほど安定するが、計算が重くなる」予算のつまみです。

### 6. 勾配ブースティング: 学習率と木の数

**ねらい** — 学習率 (1 本の木がどれだけ修正するか) と木の数 (何回修正するか) はセットで決まることを見る。ランダムフォレストと違い、木を増やしすぎると過学習することも確かめる。

**設定**
- データ: Moons、サンプル数 **400**、ノイズ **0.40**、シード 42、テストの割合 0.30 (テストは 120 点)
- モデル: 勾配ブースティング。木の深さ (max_depth) = 3、各木に使うデータの割合 (subsample) = 1.0 (いずれも既定)
- 学習率 (learning_rate) を **0.01 / 0.1 / 1.0**、木の数 (n_estimators) を **10 / 50 / 500** として、9 通りを試す

**観察すること** (訓練 / テスト)

| learning_rate \ 木の数 | 10 | 50 | 500 |
|---|---|---|---|
| 0.01 | 0.843 / 0.850 | 0.843 / 0.850 | 0.907 / 0.883 |
| 0.1 | 0.843 / 0.858 | 0.904 / 0.883 | 1.000 / 0.792 |
| 1.0 | 0.939 / 0.792 | 1.000 / 0.817 | 1.000 / 0.767 |

- 「学習率 0.1 × 50 本」と「学習率 0.01 × 500 本」は、訓練もテストもほぼ同じ結果になります (0.904 / 0.883 と 0.907 / 0.883)。学習率を 1/10 にすると、同じところまで進むのに約 10 倍の木が要ります。
- 学習率 0.01 では、50 本でも木 10 本のときとほとんど変わりません。修正の歩幅が小さすぎて、まだ進んでいないからです。
- 学習率 0.1 で 500 本まで増やすと、訓練は 1.000 になり、テストは 0.792 に下がります。境界には、ノイズの点を拾う細い縞や小さな長方形がたくさん現れます。
- 学習率 1.0 では 10 本で訓練 0.939 に達しますが、テストは 0.792 です。
- 次に、学習率 0.1・木の数 **200** にして「木の数と正解率 / 損失」の図を見てください (訓練 1.000 / テスト 0.825)。右の損失 (log-loss) の図では、訓練の損失は木を増やすほど 0 に近づきます。一方、交差検証 (訓練データだけを使った 3-fold) の損失は、25 本付近で最小になってから上がっていきます。★ はこの交差検証で選んだ木の数 (25 本) です。木の数 500 では計算時間の都合で交差検証が省略され、図の下にその旨が表示されます。
- テストの損失が最小になる木の数 (57 本) にも印がありますが、これは **（参考）** です。テストの曲線を見て木の数を選ぶと、テストの結果を使ってモデルを選んだことになり、テストの成績が楽観的になります ([実験 10](#exp-test-once))。木の数は ★ のように、訓練データの中の検証で選びます。

**なぜそうなるか** — 勾配ブースティングは、それまでの予測の誤り (損失の勾配) を次の浅い木で少しずつ修正していきます。学習率は 1 回の修正の歩幅で、木の数は歩数です。歩幅を小さくすると、同じ距離を進むのに多くの歩数 (計算) が要ります。歩幅が大きいと数歩で訓練データに合いきってしまい、行き過ぎた修正がそのまま残ります。ランダムフォレストは独立な木の **平均** なので、木を増やしてもばらつきが減るだけです。ブースティングは誤りを **足し合わせて** 直していくので、木を増やすほど訓練データのノイズまで直しにいき、過学習が進みます。10 シードの平均でも、学習率 0.1 のテストの正解率は 50 本で 0.852、500 本で 0.837 と、同じ向きの結果になりました。

### 7. SVM: RBF カーネルの gamma

**ねらい** — RBF カーネルの gamma (1 点の影響が届く範囲) で、境界の細かさとサポートベクターの数がどう変わるかを見る。

**設定**
- データ: Moons、サンプル数 200、ノイズ **0.30**、シード 42、テストの割合 0.30
- モデル: サポートベクターマシン (SVM)。カーネル (kernel) = rbf、正則化の逆数 (C) = 1
- gamma を **0.1 → 1 → 10 → 100** と動かす

**観察すること**

| gamma | 訓練 | テスト | サポートベクター数 (訓練 140 点中) |
|---|---|---|---|
| 0.1 | 0.807 | 0.883 | 78 |
| 1 | 0.921 | 0.917 | 59 |
| 10 | 0.929 | 0.867 | 81 |
| 100 | 1.000 | 0.800 | 134 |

- gamma = 0.1 では境界がほぼ直線に近いゆるやかな曲線で、月の形を曲げきれません (訓練 0.807)。
- gamma = 1 では境界が月の形に沿い、サポートベクター数は最小 (59) になります。
- gamma = 100 では各訓練点の周りに小さな島ができ、ほぼ全ての点 (134 / 140) がサポートベクターになります。訓練 1.000、テスト 0.800 の過学習です。

**なぜそうなるか** — RBF カーネルの決定関数は、サポートベクターを中心とする釣鐘形の関数の重み付き和です。gamma はその釣鐘の細さで、影響範囲はおよそ 1/√gamma です。gamma が小さいと 1 点の影響がデータ全体に広がり、境界は単純になります。gamma が大きいと 1 点の影響がその点のすぐ近くにしか届かないので、訓練点を 1 つずつ囲めてしまいます。そうなると、どの点も境界を決めるのに必要になり、サポートベクターが増えます。**発展**: C も一緒に動かしてみてください。gamma と C はどちらも「境界の複雑さ」を上げるつまみなので、良い組み合わせは 1 本の斜めの帯のようになります。

<a id="exp-mlp"></a>

### 8. ニューラルネットワーク: 恒等関数と ReLU

**ねらい** — 活性化関数が非線形でなければ、層をいくら重ねても直線の境界しか引けないことを確かめる。

**設定**
- データ: Moons、サンプル数 200、ノイズ 0.20 (既定)、シード 42、テストの割合 0.30
- モデル: ニューラルネットワーク (MLP)。1 層あたりのニューロン数 = 16、その他は既定
- 次の 4 通りを比べる: 活性化関数 = **恒等関数 (identity)** で隠れ層 **1 → 3**、次に **ReLU** で隠れ層 **1 → 3**

**観察すること**

| 活性化関数 | 隠れ層の数 | 訓練 | テスト | 境界 |
|---|---|---|---|---|
| identity | 1 | 0.807 | 0.900 | 直線 |
| identity | 3 | 0.807 | 0.900 | 直線 |
| ReLU | 1 | 0.964 | 0.983 | 月に沿った折れ線 |
| ReLU | 3 | 1.000 | 0.967 | 月に沿った折れ線 |

- identity では、隠れ層を 1 層から 3 層にしても境界は直線のままで、訓練の正解率も 0.807 のまま変わりません。
- 「第 1 隠れ層の各ニューロンの出力」の図では、identity の各ニューロンの出力は一方向に明るさが変わるだけのグラデーションです。ReLU では各ニューロンが濃い灰色の破線 (ReLU が働き始める線) の片側でだけ値を出し、反対側では 0 になります。決定境界がまっすぐな線分をつないだ折れ線になっているのは、この折れ目を組み合わせているからです。

**なぜそうなるか** — 恒等関数の層は、入力に行列をかけてバイアスを足すだけの線形変換です。線形変換を何回重ねても 1 回の線形変換と同じなので、ネットワーク全体はロジスティック回帰と同じ「直線の境界」しか表せません。ReLU (max(0, z)) は z = 0 で折れ曲がる非線形関数です。この折れ目を持つニューロンを足し合わせると、折れ線で任意の曲線に近い境界が作れます。

## ハイパーパラメータ探索

<a id="exp-grid-random"></a>

### 9. グリッドサーチとランダムサーチ

**ねらい** — 同じ試行回数でも、グリッドサーチは各軸の値を少ししか試せないことを見る。一方、ランダムサーチは試行のたびに全部の軸の値が変わる (Bergstra & Bengio, 2012)。あわせて、スコアの差が偶然の範囲かどうかを確かめる。

**設定**
- データ: Moons、サンプル数 **500**、ノイズ **0.40**、シード 42、テストの割合 0.30
- ページ: ハイパーパラメータ探索。モデル = 決定木、横軸のパラメータ = 木の深さ (max_depth)、縦軸のパラメータ = 葉の最小サンプル数 (min_samples_leaf)、分割基準 = gini
- 探索手法 = Grid・Random・TPE の 3 つ、手法ごとの試行回数 = **9**、CV の分割数 (k) = 5、評価指標 = 正解率、探索のシード = 0、全探索マップ（参考）も計算する
- 「探索を実行」を押し、③ 探索の比較 タブを見る

**観察すること**
- 全探索マップ（参考）を見てください。右側の列ほど同じ値が横に並んでいます。木は、それ以上分けられなくなると、max_depth に届く前に止まります (この訓練データ 350 点では、min_samples_leaf = 1 で深さ 15、7 で深さ 7)。そのため、止まる深さより大きい max_depth は、どれも同じ木になります。最良は max_depth 3・min_samples_leaf 1 で、CV は 0.837 でした。
- Grid の 9 試行は 3 × 3 の格子なので、max_depth は 1, 10, 20 の **3 種類** しか試しません。min_samples_leaf も 1, 7, 50 の 3 種類だけです。しかも、深さ 1 の 3 試行はすべて同じ木 (1 回の分割) です。min_samples_leaf が 7 と 50 の行では、max_depth 10 と 20 も同じ木になります。結果として、全試行の一覧のスコアは 9 試行で 5 種類しかありません。最良 CV は 0.817 (max_depth 10・min_samples_leaf 7) でした。
- Random の 9 試行は **8 種類** の max_depth (1, 2, 8, 11, 12, 13, 18, 19) を試しました。最良 CV は 0.831 で、max_depth 2・min_samples_leaf 21 と max_depth 11・min_samples_leaf 14 の 2 か所で同じ値が出ています (表示されるのは後者)。
- ただし、この差 (0.831 − 0.817 = 0.014) は、全探索マップ（参考）の最良点 (max_depth 3・min_samples_leaf 1) の fold 間標準偏差 (約 0.04) よりずっと小さい値です。マップの枠 (1-SE ルール（ここでは fold 間の標準偏差で測る保守的な版）) を見ると、320 点のうち 219 点が「最良と実質同点」の範囲に入っています。この 1 回の結果だけで「Random の勝ち」とは言えません。確実に言えるのは「同じ 9 試行で、Random のほうが max_depth の値を多く試した」ことです。
- 探索のシードを 0〜19 に変えて 20 回実行すると、Random の最良 CV が Grid を上回ったのは 16 回、下回ったのは 2 回で、差の平均は +0.014 でした。1 回ごとの差は小さくても、繰り返すと Random がやや有利な傾向が見えます。20 回の平均では、Random は 9 試行で 7.7 種類の max_depth を試し、Grid の 9 試行から得られる異なるスコアは 4.5 種類でした。

**なぜそうなるか** — k × k の格子では、それぞれの軸について k 種類の値しか試せません。結果が同じになる組み合わせ (ここでは、木が自然に止まる深さより大きい max_depth) を試した回は、無駄になります。ランダムサーチでは試行ごとに両方の軸の値が変わるので、n 試行で各軸の値を (ほぼ) n 種類試せます。どの軸のどの範囲が効くかは事前にわからないことが多いので、この性質が効いてきます。**発展**: ノイズを変えると、最良のハイパーパラメータ自体が動きます。モデル = k近傍法、サンプル数 500 にして、② 1つのパラメータ（検証曲線）で n_neighbors の曲線を見てください。最良の k はノイズ 0.1 / 0.2 / 0.3 で 1 / 4 / 29 と大きくなります。ノイズが多いほど、多くの近傍で平均してノイズを打ち消す必要があるからです。

<a id="exp-test-once"></a>

### 10. テストデータは最後に 1 回だけ

**ねらい** — ハイパーパラメータは CV で選び、テストデータは最後に 1 回だけ、報告のために使うことを体験する。

**設定**
- [実験 9](#exp-grid-random) の探索を実行したあと、④ テストで最終評価 タブで「テストデータで評価する」を押す
- テストデータは 150 点 (500 点の 30%) です

**観察すること**

| 手法 | 選ばれたパラメータ | 最良 CV | テスト | ± SE |
|---|---|---|---|---|
| Grid | max_depth 10・min_samples_leaf 7 | 0.817 | 0.827 | 0.031 |
| Random | max_depth 11・min_samples_leaf 14 | 0.831 | 0.880 | 0.027 |
| TPE | max_depth 11・min_samples_leaf 14 | 0.831 | 0.880 | 0.027 |

- CV では 3 手法の差 (0.014) が、全探索マップ（参考）の最良点の fold 間標準偏差 (約 0.04) より小さく、実質同点でした。一方、テストでは Grid と Random の設定の差が 0.053 に開きました。
- この差を判断するときは、2 本の誤差棒が重なるかどうかでは決められません。誤差棒は手法ごとのテストスコアの不確かさで、2 つの設定は **同じ 150 点** で評価しているからです。対応のある比較として、片方だけが正解した点の数を見ます。この例では、Grid の設定だけが正解した点が 2、Random の設定だけが正解した点が 10 でした (両方正解 122、両方不正解 16)。
- ただし、テストでの差が本物かどうかにかかわらず、テストの結果を見て「Random の設定に選び直す」ことはしません。選び直すと、テストデータも選択に使ったことになり、選んだモデルの性能を偏りなく見積もれるデータが残らないからです。テストデータは、CV で選び終えた設定を 1 回だけ評価するために使います。

**なぜそうなるか** — ④ タブの説明にあるとおり、たくさんの候補から最大値を選ぶと、選んだ値の CV スコアには偶然の上振れが含まれやすくなります (勝者の呪い)。これは多くの実行の **平均** で見える偏りです。この設定では候補どうしが CV でほぼ同点で、テスト 150 点のぶれ (1 手法あたり SE 約 0.03) のほうが大きいので、1 回の実行でははっきり見えません。探索のシードを 0〜9 に変えて 10 回実行すると、「最良 CV − テスト」の平均は −0.016 で、むしろテストのほうが少し高めでした。これは、データのシード 42 でどの点がテストに選ばれたかによる偶然の範囲です。データのシードを 0〜9 に変えると、この差は −0.059 から +0.104 まで大きく揺れ、10 通りの平均は +0.011 (CV のほうが高め) でした。偏りは、こうして多くの実行で平均したときに初めて見えてきます。テストの値が CV より高く出ても低く出ても、テストはその 1 回の結果をそのまま報告します。

### 11. Palmer Penguins: 特徴量の標準化

**ねらい** — 距離を使うモデル (k近傍法・SVM) は、数値の大きい特徴量に引きずられることを見る。単位が mm と g のように違う特徴量の組では、標準化でそれが直ることを確かめる。

**設定**
- データ: **Palmer Penguins**、特徴量の組 (おすすめの組) = **くちばしの長さ (mm) × 体重 (g)**、ランダムシード 42、テストの割合 0.30 (訓練 153 点 / テスト 66 点)
- 先に「データについて」を開いて、class の割合を確認する: 「class 1 の割合: 31%（多数派を当てるだけで正解率 0.69）」。class 0 = Adelie、class 1 = Chinstrap です。
- モデル: k近傍法 (k-NN、既定の k = 5) と、サポートベクターマシン (SVM、既定の rbf・C = 1・gamma = 1)
- 「特徴量を標準化する（距離を使う k-NN・SVM に効く）」を **ON → OFF** と切り替える (実データでは既定で ON)

**観察すること**

| モデル | 標準化 | 訓練 | テスト | 補足 |
|---|---|---|---|---|
| k-NN (k = 5) | ON | 0.980 | 0.970 | 境界は主にくちばしの長さで分ける縦向き |
| k-NN (k = 5) | OFF | 0.824 | 0.758 | 境界がほぼ横縞になる |
| SVM | ON | 0.980 | 0.970 | サポートベクター 33 個 |
| SVM | OFF | 0.993 | 0.727 | サポートベクター 147 個 (訓練 153 点中) |

- 正解率は、まず「多数派 (Adelie) を当てるだけ」の値と比べて読んでください。データカードの「多数派を当てるだけで正解率 0.69」はデータ全体での値です (このテスト 66 点だけで数えると 0.697)。
- **k-NN**: 標準化を OFF にすると、決定境界がほぼ横縞になります。拡大図の 5 つの近傍も、体重はほぼ同じで、くちばしの長さはばらばらの点になります。体重が近い点ばかりが「近い」と判定され、くちばしの長さはほとんど使われていません。テストの正解率は 0.970 から 0.758 に下がります。
- **SVM**: OFF にすると、背景はほぼ一様になり、class 1 の訓練点のまわりだけが小さく色づきます。訓練点のほぼすべて (153 点中 147 点) がサポートベクターになり、訓練の正解率は 0.993 とほぼ満点です。それなのに、新しい点ではほとんど多数派 (Adelie) と答えるだけで、テストの正解率 0.727 は、多数派を当てるだけの値 (0.69〜0.70) とほぼ同じです。訓練データを丸暗記しただけで、新しい点については何も学んでいないのとほぼ同じ状態です。
- ランダムシードを 0〜9 に変えた 10 通りの平均でも、テストの正解率は k-NN が 0.965 → 0.733、SVM が 0.971 → 0.758 と、同じ向きに下がりました。

**なぜそうなるか** — 距離 (ユークリッド距離) は、特徴量ごとの差の二乗の和です。体重 (g) の差は数百、くちばしの長さ (mm) の差は数 mm なので、標準化しないと距離はほぼ体重だけで決まります。そのため k-NN の「近い点」は体重が近い点になり、境界は体重の値だけで区切られた横縞になります。SVM の gamma は、標準化した単位 (標準偏差が 1) を前提にした値です。生の単位では、どの 2 点も gamma = 1 の感覚ではとても「遠い」ので、カーネルは各訓練点のすぐそばでしか値を持ちません。そのため訓練点は 1 点ずつ囲めますが、新しい点はどの訓練点からも遠く、決定関数はほぼ一定になって、多数派と答えるだけになります。標準化すると 2 つの特徴量が同じくらいの幅になり、どちらも距離に効くようになります。

**対照** — 同じ操作を決定木 (既定の深さ 3) や、ガウス生成モデルの LDA で行うと、「このモデルでは「特徴量を標準化する」は結果を変えません（木、LDA、Naive Bayes、reg_param = 0 の QDA は、現実的な単位の範囲では特徴量のスケールに左右されません。ロジスティック回帰と MLP はモデルの中ですでに標準化しています）。」と表示され、正解率も変わりません (決定木 0.993 / 0.955、LDA 0.974 / 0.985)。ただし、アプリはこれらのモデルには標準化を付けないので、「値が同じだった」こと自体は、スケールに左右されないことの証拠にはなりません。理由は次のとおりです。決定木は特徴量ごとのしきい値で分けるので、単位を変えても、しきい値が変わるだけで同じ分け方になります。LDA の決定境界は、特徴量ごとの拡大縮小で変わりません。この性質は、アプリの外で特徴量の単位を手で変えて学習し直すテストで確かめています (tests/test_models_teaching_claims.py)。

**発展: 正則化はスケールに依存する** — ガウス生成モデルで QDA を選び、共分散の正則化 (reg_param) を 0 より大きくしてください (例: 0.5)。
1. アプリの中: 「このモデルには標準化を適用していません。QDA の reg_param は特徴量の単位に依存するため、単位の違う特徴量の組では結果が単位の選び方で変わります。」と表示されます。このモデルには標準化が付かないので、チェックボックスの ON / OFF で結果は変わりません (訓練 0.980 / テスト 0.970)。
2. アプリの外での確認: 同じデータで、体重を g から kg に直すなど特徴量の単位を手で変えて学習し直すと、reg_param = 0.5 の QDA は、テスト 66 点のうち 2〜4 点の予測が変わりました (単位の変え方によっては 0 点)。reg_param = 0 の QDA、LDA、Naive Bayes、決定木では、どの変え方でも 0 点でした。アプリには単位を変える操作がないので、この違いは画面では見られません。
3. 理由: reg_param は、各クラスの共分散を単位行列 (円) の方向に縮めます。単位行列は特徴量の単位を考えないので、どの単位で測るかによって縮め方が変わります。

<a id="exp-feature-pair"></a>

### 12. Iris: 特徴量の組の選び方

**ねらい** — どの 2 つの特徴量を使うかで、この 2 つの特徴量で達成できる正解率の上限が、モデルより先に決まることを見る。

**設定**
- データ: **Iris** (class 0 = versicolor、class 1 = virginica。各 50%)、ランダムシード 42、テストの割合 0.30 (訓練 70 点 / テスト 30 点)、特徴量を標準化する = ON (既定)
- モデル: k近傍法 (k = 5、投票の重み = 均等 (uniform))
- 特徴量の組 (おすすめの組) を **花弁の長さ (cm) × 花弁の幅 (cm)** → **がく片の長さ (cm) × がく片の幅 (cm)** と切り替える

**観察すること**

| 特徴量の組 | 訓練 | テスト | データカード: 同じ座標にある点 |
|---|---|---|---|
| 花弁の長さ × 花弁の幅 | 0.971 | 0.900 | 35 点（うち class が食い違う点 3 点） |
| がく片の長さ × がく片の幅 | 0.800 | 0.600 | 39 点（うち class が食い違う点 24 点） |

- 花弁の組では、2 つのクラスがほぼ分かれていて、境界の近くに少し重なりがあるだけです。がく片の組では、2 つのクラスの点が大きく混ざっていて、境界が入り組んだ形になります。
- テストは 30 点しかないので、1 点で正解率が 0.033 動きます。5-fold の交差検証を 20 回繰り返した平均 (アプリの外で計算。標準化なし) でも、k-NN の正解率は花弁の組で約 0.945、がく片の組で約 0.649 でした (ロジスティック回帰でも約 0.936 と約 0.726)。モデルを変えても、がく片の組は花弁の組に届きません。
- Iris の測定値は 0.1 cm 刻みなので、同じ座標の点がたくさんあります。がく片の組では、同じ座標にありながら class が食い違う点が 24 点あります。同じ座標に別の class の点があると、どのモデルもその両方を当てることはできません。

**なぜそうなるか** — がく片の長さと幅では、versicolor と virginica の分布が大きく重なっています。重なっている場所では、同じような値の花がどちらの種類でもありうるので、どのモデルでも間違いが残ります (重なりによる避けられない誤り)。これはモデルの工夫では減らせません。減らすには、2 つのクラスを分ける情報を多く持つ特徴量 (ここでは花弁) を選ぶ必要があります。

**発展: 同じ座標で class が食い違う点と訓練の正解率** — 花弁の組には、同じ座標で class が食い違う点が 3 点あります (1 か所に重なっています)。k近傍法で投票の重みを「距離の逆数 (distance)」にすると、訓練点の予測は、距離 0 にある点 (自分と同じ座標の点) だけで決まります。
- ランダムシード 42: データカードに「訓練データの中には、同じ座標で class が食い違う点はありません（訓練の正解率を下げる原因にはなりません）」と表示され、訓練の正解率は 1.000 です。
- ランダムシード 0: 訓練データの中に、同じ座標で class が食い違う点が 2 点入ります (class 0 と class 1 が 1 点ずつ)。同じ座標にある 2 点は class が違うので、どちらを予測しても 1 点は必ず外れます。そのため訓練の正解率は 0.986 (70 点中 69 点) になり、1.0 に届きません。「k と正解率」の図の下にも、その説明が表示されます。
- 「distance 重みなら訓練の正解率は必ず 1.0」とは限らないことが分かります。どの点が訓練データに入るかは、ランダムシードで変わります。
