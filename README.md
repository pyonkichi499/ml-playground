# ML Playground

2 次元のトイデータと実データ（Palmer Penguins、Iris）で、分類アルゴリズムとハイパーパラメータの挙動を **目で見て** 学ぶための Streamlit アプリです。

- **プレイグラウンド**: 1 つのモデルのハイパーパラメータを動かし、決定境界・正解率・モデル固有の図がどう変わるかを観察する。
- **ハイパーパラメータ探索**: グリッドサーチ / ランダムサーチ / TPE を同じ条件で走らせて比べ、交差検証とテストデータの役割を学ぶ。

## 必要なもの

- [uv](https://docs.astral.sh/uv/)
- Python 3.14（`.python-version` で指定。uv が自動で用意します）

## セットアップ

```bash
uv sync
```

## 起動

```bash
uv run streamlit run app.py
```

ターミナルに表示される URL（通常は http://localhost:8501）をブラウザで開きます。ポートを変えたいときは `--server.port 8599` のように付けます。

ハイパーパラメータ探索ページの全探索マップ（参考）と検証曲線は、計算量が多いときに複数のプロセスで並列に計算します。並列数の上限は環境変数 `ML_PLAYGROUND_MAX_JOBS`（正の整数）で変えられます。既定は min(4, CPU 数の半分)（最低 1）で、1 にすると常に直列になります（例: `ML_PLAYGROUND_MAX_JOBS=1 uv run streamlit run app.py`）。

## テスト

```bash
uv run pytest -q                                   # timing (性能目標) と scale (大規模検証) 以外の全テスト
uv run pytest -m timing                            # timing (性能目標) のテストだけ（既定の実行では外れる）
uv run pytest tests/test_app_smoke.py -q           # 1 ファイルだけ
uv run pytest -q -k "knn"                          # 名前に knn を含むテストだけ
```

ページの通しテストは `streamlit.testing.v1.AppTest` で書いています（ブラウザもサーバーも不要）。timing と scale 以外の全テストは約 3〜4 分、`tests/test_app_smoke.py` だけなら約 1.5 分かかります（開発機での目安）。

所要時間の目標を確かめるテスト（`timing` マーカー付き）は、マシンの負荷で結果が揺れるため、既定の `uv run pytest` では実行しません。確かめるときは、負荷の低いときに `uv run pytest -m timing` を実行します。大きな条件（n=1000、複数のシード）での検証（`scale` マーカー、`tests/scale/`）も既定では実行しません。流すときは `uv run pytest tests/scale -m scale` のように、必ず `-m scale` を付けます（付けないと 0 件のまま終わります）。

## 画面の案内

### 共通: データの設定（サイドバー上部）

| 項目 | 範囲（既定値） |
|---|---|
| データセット | Moons / Circles / Linear Separable / Palmer Penguins / Iris（Moons）。前の 3 つは合成データ、後の 2 つは実データ |
| サンプル数 (n_samples) | 50〜1000（200）。実データでは使わない（件数は固定。スライダーは無効になる） |
| ノイズの強さ (noise) | 0.0〜0.5（0.2）。実データでは使わない |
| ランダムシード | 0〜10000（42）。訓練 / テストの分け方（合成データでは点の生成も）を決める |
| テストデータの割合 | 0.0〜0.5（0.3）。0 にするとテストデータなし |
| 特徴量の組 (おすすめの組) | 実データだけ。2 つの特徴量の組を選ぶ。「自由に選ぶ」にすると、横軸と縦軸の特徴量を別々に選べる |
| 特徴量を標準化する（距離を使う k-NN・SVM に効く） | 既定は、実データでオン、合成データでオフ |

この設定は 2 つのページで共通で、ページを切り替えても保持されます。

**実データ**: どちらも元は 3 クラスのデータから 2 クラスを取り出し、4 つの特徴量から 2 つを選んで 2 次元にしています。

- **Palmer Penguins**: 南極のパーマー群島で測ったペンギンの体の大きさ。アデリーペンギン（class 0、青）とヒゲペンギン（class 1、橙）を見分けます（ジェンツーペンギンは使いません）。特徴量は、くちばしの長さ・高さ、フリッパー（翼）の長さ、体重。数値に欠損のある行は除いています。
- **Iris**: Fisher (1936) のアヤメの花の測定値。Iris versicolor（class 0）と Iris virginica（class 1）を見分けます（setosa は使いません）。特徴量は、がく片と花弁の長さ・幅。

実データを選ぶと、プレイグラウンドに「データについて」の欄が出ます。件数、class 0 / class 1 が元のどの種か、class 1 の割合、同じ座標に重なっている点の数（あれば）、出典が書いてあります。

**標準化**: 「特徴量を標準化する」が効くのは、距離を使う k-NN と SVM だけです（交差検証では fold ごとに訓練側だけで標準化するので、検証データの情報は漏れません）。ほかのモデルでは、オンにしても標準化は適用されず、プレイグラウンドにその理由が表示されます。木、LDA、Naive Bayes、reg_param = 0 の QDA は特徴量のスケールにほぼ左右されず、ロジスティック回帰と MLP はモデルの中ですでに標準化しています。reg_param > 0 の QDA だけは単位に依存しますが、標準化は適用していません。

### プレイグラウンド

1. サイドバーの **モデル** で 8 つのモデルから 1 つを選び、その下のハイパーパラメータを動かします（多くの項目は ? にカーソルを合わせると説明が出ます）。
2. 上部にモデルの一言説明、**訓練データの正解率 / テストデータの正解率**（差も表示）と、モデル固有の指標が並びます。
3. **決定境界** の図: 背景色は予測（多くのモデルでは class 1 の確率）、● が訓練データ、▲ がテストデータです。図の右に、そのモデルでの背景色の意味が書いてあります。
4. その下に、モデル固有の図（例: 決定木のツリー構造、k と正解率、損失曲線）が続きます。

訓練の正解率が高いのにテストの正解率が低ければ、過学習のサインです。

設定によっては学習できないことがあります。そのときは図の代わりに赤い案内が出て、直し方が書かれています（例: ガウス生成モデルの QDA で reg_param = 0 のまま、クラスの点がほぼ一直線に並んだとき）。

### ハイパーパラメータ探索

同じデータ・同じ fold 分割で、3 つの探索手法（グリッドサーチ / ランダムサーチ / TPE）を試行回数をそろえて走らせ、比べます。

**サイドバー「探索の設定」**

- **モデル**: 8 モデルすべてから選べます。
- **横軸のパラメータ / 縦軸のパラメータ**: 探索するパラメータです。縦軸を「なし」にすると 1 つのパラメータだけを探索します（1 次元）。2 つ選ぶと 2 次元の探索になります。初期値は、そのモデルの探索できる数値パラメータの先頭 2 つです（例: ランダムフォレストは max_depth × min_samples_leaf。数値パラメータが 1 つだけの k近傍法とガウス生成モデルは 1 次元から始まります）。
- **固定するパラメータ**: 探索しないパラメータの値です。初期値はモデルの既定値です。ただしランダムフォレストの木の数 (n_estimators) だけは、1 回の評価を軽くするため探索ページでの初期値が 50 です（プレイグラウンドの既定は 100）。
- **探索手法**: Grid / Random / TPE から 1 つ以上選びます。
- **手法ごとの試行回数**: 2 次元のときは 9〜49 から選びます（Grid は各軸 √n 点の格子）。1 次元のときは 3 以上です。初期値と上限はモデルの探索コストで決まります（初期値: low 25、medium 16、high 9 ／ 上限: low 49、medium 25、high 16）。予定の試行回数と所要時間の目安がボタンの上に表示され、目安が 30 秒を超えると、実行前に警告と短くする方法が出ます。整数の軸では格子の値が丸めで重なるので、Grid の回数が減ることがあります。
- **CV の分割数 (k)**（3 / 5 / 10）と **評価指標**（正解率 / ROC AUC）: 1 fold の検証データが 10 点未満になると警告が出ます。
- **探索のシード**: CV の分け方と、Random / TPE の乱数を決めます。変えて再実行すると、手法の順位が入れ替わるかどうか確かめられます。
- **全探索マップ（参考）も計算する**: 粗い格子の全点を交差検証した「比較用の背景」です。探索手法はこの結果を知りません。探索コストが high のモデル（MLP）では、既定でオフです。
- **探索を実行**: 実行中は画面右上の **Stop** で止められます。

**タブ**

| タブ | 学べること |
|---|---|
| ① データの分け方 | 訓練データ・検証（k-fold 交差検証）・テストデータの役割。どの点がどの fold の検証に回るかを図で見る。前処理を CV の外で済ませると情報が漏れる理由 |
| ② 1つのパラメータ（検証曲線） | 横軸のパラメータだけを動かしたときの訓練スコアと CV スコア。未学習 ↔ 過学習、fold 間のばらつき。最小・最良・最大の値での決定境界と、fold ごとのスコアも見られる。探索コストが medium / high のモデルはボタンを押したときだけ計算する |
| ③ 探索の比較 | 各手法がどこを試したか（ヒートマップ。1 次元では曲線上の点）と、「ここまでの最良 CV」の推移（レース図）。背景は CV スコア / 訓練スコア / 訓練 − CV（過学習の大きさ）で切り替えられる。レース図の横軸は試行番号か累積学習時間を選ぶ。スライダーで途中の状態を再生できる。全探索マップ（参考）を計算したときは、最良と実質同点の範囲（1-SE ルール。ここでは fold 間の標準偏差で測る保守的な版）を枠（1 次元では曲線の太い帯）で示す |
| ④ テストで最終評価 | 各手法の最良パラメータを訓練データ全体で学習し直し、テストデータで 1 回だけ評価する。最良の CV スコアが楽観的になる理由（勝者の呪い）と、テストの誤差の大きさ（± 1 標準誤差）。手法どうしは同じテスト点で評価しているので、差があるかは対応のある比較で見る必要があり、誤差棒の重なりだけでは決められない |

**読むときの注意**

- **全探索マップ（参考）は正しい答えではありません。** 1 通りの fold 分割によるノイズを含む推定値です。格子の間の値は調べていません。ノイズを含む多数の値から最大を取るので、最良値は楽観的に出やすくなります。そのため、探索手法がこの値を超えることもあります。
- 手法間の CV スコアの差が fold 間のばらつき（±1 標準偏差）より小さければ、その差は偶然の範囲かもしれません。最良と実質同点の範囲の中で迷ったら、単純な方を選びます（1-SE ルール。ここでは fold 間の標準偏差で測る保守的な版）。
- **テストは最後に 1 回だけ見ます。** テストの結果を見てパラメータを選び直すと、テストも選択に使ったことになります。そうなると、偏りのない評価が残りません。
- **中断された結果**: Stop や、実行中のウィジェット操作で探索が止まっても、そこまでの試行は残ります。次の画面で「中断された結果 (n/N)」として表示され、「中断された結果を破棄」で消せます。テストでの評価（④）は、最後まで実行した結果に対してだけ行えます。
- サイドバーの設定を前回の実行から変えると警告が出ます。表示は前回の結果のまま残ります。

## モデル一覧

メニューの並び順です。「探索コスト」はハイパーパラメータ探索ページでの計算量の区分で、探索の細かさと試行回数の上限が決まります（low → medium → high の順に粗く・少なくなります）。

| モデル | 何が学べるか | 主なハイパーパラメータ | 探索コスト |
|---|---|---|---|
| ロジスティック回帰 | 特徴量の重み付き和 z をシグモイド関数で確率に変える線形モデル。多項式特徴量で曲線の境界も引けるが、次数を上げるほど過学習しやすく、正則化で抑える。L2 は係数を全体に小さく、L1 は効かない係数をちょうど 0 にする（特徴選択） | 多項式の次数 degree, 正則化の逆数 C, penalty (L2 / L1) | low |
| k近傍法 (k-NN) | 学習 = データを覚えるだけ。最も近い k 点の多数決で決める。k が小さいとギザギザで過学習、大きいと滑らかだが細部を見落とす。距離の測り方（p）と、近い点ほど強く投票する重み付け | n_neighbors (k), weights, p | low |
| ガウス生成モデル (Naive Bayes / LDA / QDA) | 各クラスが正規分布から生まれたと仮定し、ベイズの定理で確率を出す生成モデル。共分散（楕円の形）の仮定で境界が変わる: 共通の楕円 (LDA) なら直線、クラス別 (QDA・Naive Bayes) なら 2 次曲線。事前確率 P(y) を動かすと境界がずれる | variant, reg_param (QDA), 事前確率 | low |
| 決定木 | 「x1 ≤ 0.3 か？」のような質問を繰り返してデータを分割する。境界は軸に平行な階段状。深いほど訓練データにぴったり合う（過学習しやすい） | max_depth, min_samples_leaf, criterion | low |
| ランダムフォレスト | ブートストラップと特徴量のランダム化で少しずつ違う木を育て、多数の決定木の予測確率を平均する（葉が純粋になるまで育てた木なら多数決と同じ）。1 本 1 本はギザギザでも、平均すると分散が減って境界がなめらかになる。学習に使われなかった点 (OOB) で汎化性能を見積もれる | n_estimators, max_depth, max_features, bootstrap, min_samples_leaf | medium |
| 勾配ブースティング | 浅い木を 1 本ずつ足し、それまでの誤差（損失の勾配）を次の木が修正する。learning_rate × 木の数のトレードオフ。ランダムフォレストと違い、木を増やしすぎると過学習する。subsample < 1 で確率的勾配ブースティング | n_estimators, learning_rate, max_depth, subsample | medium |
| サポートベクターマシン (SVM) | クラス間のすき間（マージン）が最大になる境界を引く。境界を決めているのはサポートベクターだけ。カーネルで曲線の境界も引ける（rbf の gamma が大きいほど 1 点の影響範囲が狭い） | kernel, C, gamma, degree (poly) | low |
| ニューラルネットワーク (MLP) | 「重み付き和 → 活性化関数」の層を重ねて曲がった境界を作る。活性化関数が identity だと何層でも直線。損失が非凸なので、シードや学習率で行き着く解が変わる。損失曲線で収束を確かめる | 隠れ層の数・ニューロン数, activation, alpha, learning_rate_init, max_iter, seed | high |

## モデルを追加するには

モデルはプラグインになっていて、アプリ側の変更は不要です（`models/base.py` の docstring より）。

1. `models/<name>.py` に `BaseModel` のサブクラスを実装する
2. クラスに `@register` デコレータを付ける
3. `models/__init__.py` でそのモジュールを import する（import の順 = メニューの並び順）

実装のルール:

- `name`（メニューに出る名前）と `summary`（そのモデルが教える概念の一言説明）を書く。
- 必須の抽象メソッドは `render_params(st)` と `build(params)` の 2 つ。`render_params` はサイドバーで選んだ値の dict を返し、`build` は未学習の推定器（Pipeline 可）を返す。
- `default_params` に `build()` が受け取る全パラメータの既定値を書く（サイドバーの初期値と、探索時の固定値の唯一の情報源）。
- `build(params)` は `default_params` の一部だけを上書きした dict でも動くこと（`{**self.default_params, **params}`）。探索では無効な条件付きパラメータを除いた dict が渡ります。
- `render_params(st)` のウィジェットには必ず `key=self.key("<param>"), persist_state="session"` を付ける。
- 乱数を使う推定器には `random_state` を固定して渡す。
- 探索では `build()` の結果（`scale_sensitive = True` のモデルで標準化がオンなら、`StandardScaler` を前段に付けたもの）に対して `cross_validate` が直接呼ばれ、`fit` の上書きは通らない。k のクランプやソルバーの選択などは推定器の中に書き、`build()` だけで完結させる。
- 探索できるパラメータは `@classmethod` の `search_space()` で `ParamSpec`（`tuning/space.py`）のリストとして宣言する（数値のパラメータが 1 つもなければ、ハイパーパラメータ探索ページのモデル一覧に出ません）。計算の重さを `tuning_cost`（`"low"` / `"medium"` / `"high"`）で示す。
- 必要なら `metrics(ctx)` と `extra_plots(ctx)` でモデル固有の指標と図を追加する（テストデータがない場合も動くこと）。
- 画面の文言は日本語、図の中の文字は英語。

詳しい規約と scikit-learn 1.9 での注意点は [CLAUDE.md](CLAUDE.md) にあります。参考実装は `models/decision_tree.py` と `models/svm.py` です。
